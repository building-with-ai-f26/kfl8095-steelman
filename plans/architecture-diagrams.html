Proposed system architecture

Browsers hold each reader’s view. One application service validates changes. Postgres stores the shared state.

How readers stay in sync

Load a snapshot at sequence S; poll every ~3 seconds for rows with changed_seq > S. Reads return a consistent snapshot. A read recalculates the shared order when its 60-second interval is due; the browser holds its layout until Update.

How writes stay consistent

One transaction locks the board counter, checks permissions and stale state, updates data and counts, stamps changed rows, then commits. Set-value writes make retries safe. Vote keys enforce one vote per person and target; assessments also name the revision.
