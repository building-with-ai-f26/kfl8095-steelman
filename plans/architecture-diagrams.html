Architecture

How the real product is put together: one service, one database, and a board that stays still for its reader while everyone else keeps voting.

Drawn from plans/architecture.md as of November 11, 2026. No code exists yet; this is the design.

The whole system

One container runs everything we write. It talks to one Postgres database. Everything else is a service we call, not one we run.

  • About $15–20 a month for the class trial
  • 30 readers polling is about 10 requests a second
  • One region, us-central1
  • No background workers in the MVP

What is stored

Each of the three judgments attaches to a different thing. Importance belongs to an argument, articulation to a wording, and credibility to one exact revision of that wording.

Live, but held still

Every write takes the board's next change number and stamps it on the rows it touched. A reader holds a number and asks for everything stamped after it. Counts update where they are; the order only moves when the reader says so.

From a change to production

A pull request is tested only against a database it starts and throws away. Staging changes when main does. Production changes when you say so.

How agents work the backlog

An item in the build plan's backlog is already approved. An agent takes the next one, proves it with tests it wrote first, and moves on without waiting for you.

An agent stops and asks when

  • a fix has failed twice
  • the item can't be built as designed
  • an existing test, screenshot, or migration would change
  • a new package is needed at run time
  • data would be dropped, or a role would gain a power
  • it costs money, needs an account, or releases to production

What stays with you

  • Once: the domain, GCP billing, Google's consent screen, Resend's DNS records, GitHub branch rules
  • Each release: approving production
  • Each milestone: a real phone, a real screen reader, a classmate's school account
