# Steelman identity brief

A short record of how Steelman should look and feel, and why. Change it when a decision changes.

## Files

- [`tokens.css`](tokens.css): every color, typeface, and texture value. The product page links it; `scripts/sync-prototype.py` copies it into the prototype.
- [`logo.svg`](logo.svg): the honeycomb mark. The same SVG is inlined in each page's header and, as a data URI, used for the favicon.
- [`contours.svg`](contours.svg): the canvas contour tile. Regenerate with `python3 scripts/make-contours.py`, then run the sync script.
- [`index.html`](index.html): the specimen. It shows each token and component using the prototype's real stylesheet, and lets you try new color values live. Serve `docs/` over HTTP to view it (see `AGENTS.md`).

## Principles

1. **Remove text wherever it is not necessary.** If a position, shape, or mark can carry the meaning, don't add a label. Labels that would need a person or a model to invent them (summaries, version names) don't belong.
2. **The three judgments are the visual language.** Credibility, importance, and articulation each have one control and one place:
   - credibility is the evidence mark in a card's footer;
   - importance runs top to bottom, voted beside each row;
   - articulation runs left to right, voted under each version.
   Importance and articulation share one vote control, a quarter turn apart, and one arrowhead.
3. **Everything stays physically inside the diagram.** Detail unfolds in place (a stack fans out, a card extends downward) rather than opening a new view.
4. **Grayscale first; color only carries meaning.** Three meanings so far: evidence strength, AI, and which space a board belongs to (its canvas). Nothing decorative is colored.
5. **Editorial, not app-like.** Inspiration: NYT graphics and maps, early FiveThirtyEight. Serif for questions and axis labels, a clean sans for claims and controls, generous whitespace, thin rules.

## Current choices

| Area | Choice |
| --- | --- |
| Logo | A four-cell honeycomb diamond beside the serif "steelman.": solid top-left (strongest), two outlined cells, and a dashed cell bottom-right (weakest). The dashed outline uses three square dashes per edge, with a dash centered on every corner (`pathLength` plus a half-dash offset). Replaced the black "s" square. |
| Type | Source Serif 4 (questions, headings; light italic lowercase for axis labels). Libre Franklin (claims, interface). |
| Surfaces | Topographic canvas: quiet white contour lines on light warm gray (`#e7e6e3`, lines at 20% white, raised from 12% so the texture reads a little more) under a fine grain. The seamless 480 px tile (22 contour levels) is generated by `scripts/make-contours.py`, which writes `contours.svg` and embeds it in the `--sm-contours` token. Column panels use `--sm-panel`, and the axis halos match it; near-white cards with rounded corners. Everything raised above the canvas casts a layered drop shadow from five elevation tokens (small controls, cards, card hover, option columns, headers). Graph paper (one line system too many) and mottled paper were tried and set aside; a hex dot lattice, a halftone fade, framed paper, paper fibers, faint contours, and linen were also considered. |
| Lines | Connector wires `#767676`. Hairline axes with a swept arrowhead; gray connector wires between question, options, and arguments. Axes use map-style halos (labels, line, and arrowheads knock out the texture behind them) instead of boxes; a box, a cleared lane, moving the axis outside the column, and a texture fade were compared and set aside. |
| Motion | Physical and short: columns widen, stacks fan out, cards extend. Reduced-motion users get instant changes. Textures are static. |

## Decisions from the November 7 interview (in the prototype)

| Topic | Decision |
| --- | --- |
| Evidence mark | A four-segment **support meter** replaces the dossier icon: filled segments = share of assessments that find the wording supported. Colored on a diverging scale, red `#E06C78` (not supported) → neutral gray (contested) → green `#3d9a64` (supported). The segment count carries the value too, so it works for red–green colorblind readers. Navy was tried first and dropped as unintuitive. Every claim uses the same meter; there is no separate "value judgment" category (deciding which claims are values would need an invented, contestable label). Claims evidence can't settle simply stay unreviewed or contested. |
| AI | Ochre `--sm-ai` `#C9952B` (text `--sm-ai-ink`, hover `--sm-ai-hover`), always with the **robot** icon (Lucide `bot`), so color never carries the meaning alone. Ochre means "AI did this" and nothing else. When AI checks are on, every card carries one, so the mark is small and wordless: the ochre robot (who) plus a 9 px **verdict dot** (what) in the evidence meter's colors and fill: green and full = supports, gray and half = partly supports, red and empty = doesn't support, dashed = nothing to check. Fill repeats what color says, for colorblind readers. It sits right after the evidence meter, on each source row AI read, and beside "Does the evidence back this wording?", and explains itself on hover (tap on touch screens). An **AI draft** card adds a dotted ochre border and an "AI draft" tag whose hover gives its basis and limits. There is no separate AI panel. Tried and dropped: a sparkle (read as decoration, and the prototype already uses sparkles for **New**), and an "AI Partly" text pill (too loud when it appears on every card). Light blue (PRD v0.4) was replaced by ochre. |
| Importance and articulation | No color. A hex texture per column carries both, from real votes: **hex size = importance** (per row), **hex darkness = articulation** (per version, across an unfolded row). Credibility is not part of the texture. Hexagons are **outlined**, not filled, to keep the texture quiet. Size runs from pinpoints (least important idea on the board) to touching cells (most important) on a curve that exaggerates the difference. The best version always matches a single-version row's tone, and weaker versions fade toward 15% of it, so having alternatives never makes an idea look weaker. |
| Axis arrows | Keep both arrows; the texture shows values, the arrows name the axes. |
| Reactivity | Static textures. They redraw when votes change, without animation. No cursor effects. |
| Header boxes | **Inverted**: near-black boxes with white serif type for the question and option headers. (Sharp and ruled was compared and set aside.) |

## Decisions from the November 9 design audit (batch A, in the prototype)

| Topic | Decision |
| --- | --- |
| Italics | No italic serif anywhere. The serif is for questions and headings only. What italics used to set apart (dates, "Draft", empty states, deleted comments) is now Libre Franklin Light (300) in `--sm-quiet` (#707070, 4.9:1 on white). Vote messages ("Important.") are 12px medium sans. |
| Dates | Relative everywhere ("4d ago"), with the full date on hover, using even-width figures. The prototype's "now" is fixed at November 9, 2026. |
| Axis labels | Small tracked capitals (11px, medium) instead of light lowercase italic. Where the axes sit is batch B. |
| Type scale | 11, 12, 13, 14, 16, 20, 24, 32 px, plus the 23px wordmark. Initials alone use 10px, in circles of at least 24px. Nothing else is below 11px. |
| Host fonts | The page hosting the prototype sets `p`, `li`, and headings to the system font. Inside the prototype they inherit Libre Franklin. |
| Typing | A writer shows as a still "•••" bubble beside their badge, with dots pulsing in place (no motion for reduced-motion users). The moving named cursor was removed as distracting. |
| Icons | Lucide icons use a 1.75 stroke throughout. |

## Decisions from the November 9 design audit (batch B, in the prototype)

| Topic | Decision |
| --- | --- |
| Axes | Map-style halos are gone: they cut jagged holes in the hexagon texture. The importance axis runs in the canvas margin, outside the first column's panel. The articulation axis is a key strip ("BEST ARTICULATION ← → WEAKER") with its own white background and pill outline, above an unfolded row. On phones, "MORE IMPORTANT" is a small pill above the first card. This revisits the earlier "moving the axis outside the column" and "a box" studies, which predate the hexagon texture. |
| Elevation | Flatter. `--sm-shadow-sm` is a single 1px shadow, used for list items, the question and option headers, and controls. Cards keep a soft two-layer `--sm-shadow`. Option panels barely lift. `--sm-shadow-lg` is for floating things only: menus, Share, comments, the create sheet. The sort bar has no shadow. List items lift on hover. |
| Corners | Three radii: 6 px (controls, chips, headers), 10 px (cards, panels, list items, sheets), and pill. The board miniatures keep their small radii. |
| List controls | The sort bar is text only. Your vote shows as a filled arrow with a bolder score. |
| Phone axes | No axis arrows at 640 px and below. Each option header has a light subline, "Most important first". An unfolded row is a snapping carousel with a caption ("1 of 3 · best articulated", "2 of 3", "3 of 3 · weakest", "Add a better version") and dots, beside the fold button. The pills tried first were cramped: the arrowheads collapsed into "<=>" and the key was cut off. |
| Phone board header | Logo mark without the word, no zoom switch, Share as an icon. |
| Comments panel | On wide screens the canvas makes room for the panel, instead of leaving a white strip beside it. |

## Decisions from the November 9 design audit (batch C, in the prototype)

| Topic | Decision |
| --- | --- |
| Space canvases | Each space gives its boards a canvas, a pale tint plus a texture, so a board and its miniature show where it lives. POD 6: warm stone `--sm-canvas-stone` + contours (the original). Northwind Studio: cool gray + dot grid. Personal: sand + grain only. Brooklyn Streets: slate blue + contours. Campus Life: sage + linen hatching. Future of Work: lilac + dot grid. Tints are low in saturation and clear of the evidence red and green and the AI ochre. They were nudged up once after the first values were indistinguishable at miniature size. The textures are `--sm-contours`, `--sm-tex-dots`, `--sm-tex-linen`, and `--sm-grain`; contours, dots, and linen were strengthened slightly (contour lines 12% → 20% white, dots 16% → 24%, linen 6%/3% → 10%/5%). |
| Where the canvas shows | The board, its miniature in the list, a 14 px swatch beside each space in the sidebar, the banner on the space's card, and the New steelman sheet (it follows the chosen space). Space tags stay ink on white. |
| The list | Plain gray (`--sm-list-bg` #ebebeb), with no texture, so the miniatures carry the color. |
| Right rail | At 1280 px and wider: on Home, "Needs your help" (up to four boards in your spaces and joined communities where an option has fewer than two arguments, thinnest first) and "Your drafts" (Personal). On a space, its card (canvas banner, name, about, privacy, members, Join) and its own "Needs your help". The dark space header is gone. Below 1280 px the space card sits above the list. |

## Decisions from the second audit (batch D, in the prototype)

| Topic | Decision |
| --- | --- |
| Motion | Three speeds and one curve, as tokens: `--sm-fast` 120 ms (hovers), `--sm-medium` 200 ms (panels, small reveals), `--sm-slow` 420 ms (zoom, unfold, reorder), `--sm-ease`. The prototype's JavaScript reads them. The only other timing is how long a vote message stays (1.4 s). |
| Hover | Every pressable element eases background, color, border, shadow, and lift over `--sm-fast`. In the list, the item lifts and its miniature rises with it; the space tag gets a quiet gray fill; the title no longer underlines. |
| Panels | Share, comments, settings, menus, and the create sheet arrive with a 200 ms fade and 4 px rise; the create backdrop fades. They close instantly. Non-modal panels close on Escape or a click outside (the click still reaches what it was aimed at). Only the create sheet dims the page. |
| Presence | Badges update in place. Only someone who just arrived, or just started writing, pops in, instead of every badge replaying its animation on each move. |
| Opening a board | Jump to the top first, then grow the board from where its miniature was on screen. |
| Avatars | One avatar: a light circle with two initials, everywhere (board header, comments, Share, faces, presence). Only you are dark. |
| Buttons | One primary (dark) and one secondary (outlined) style, 32 px, 13 px, 6 px corners. Join, Invite, Create, and Comment follow it. |
| Titles and labels | Panel titles are 16 px serif (Comments, Settings, Share, New steelman). Group headings are 11 px tracked capitals (sidebar, rail, Share, Context, Evidence, Example board). Form field labels stay sentence case. |
| Visibility words | One set everywhere: "Invited only", "Everyone in POD 6", "Anyone with the link". Share's hint follows the role: "Everyone in POD 6 can read, comment, vote, and write." |
| Concision | The board header no longer repeats the space; the breadcrumb names it and the pill says who can see it. Miniatures show the board's shape and canvas, not a block per argument (the chips carry the counts). Shorter create hints, rail reasons ("Keep five days · 1 argument"), and Settings ("Sharing and access →"). Discover is removed until it exists. |
| Empty comment buttons | Visible at 40% on cards with no comments, full on hover or focus, so touch screens can find them. |
| Phone importance caption | Below each option header: a small down arrow centered over the importance votes and "Most important first", in the same quiet voice as the version caption. It no longer sits inside the dark header. |

## Open questions

- **Texture strength.** Cell size, contrast, and articulation range are tunable on the specimen; settle values before moving the texture into the prototype.
- **Product page type.** The product page still uses Georgia and Helvetica; align once the identity settles.

## Tried and set aside

- **November 7, 2026: topographic background and a five-color palette.** Interactive contour lines on the canvas, with rose, sage, and navy gradients on the axes. A follow-up direction was sketched but not built: a dark, dense, static map whose lines lighten under the cursor, with red → blue credibility, white → green importance, and white → black articulation. The first version was reverted and the second set aside in favor of setting up these tokens and deciding what color means first. Either direction can be retried in the specimen.

## How to try a change

1. Open the specimen and adjust a swatch, or edit `tokens.css` directly.
2. Check the result in the specimen, then in the prototype.
3. Run `python3 scripts/sync-prototype.py`, record what you checked in `tests/build-1-manual.md`, and note the decision here.
